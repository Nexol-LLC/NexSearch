# NexSearch 2.0 — перенос 1.6.7 на Rust + Tauri

Версия 2.0.0 сохраняет привычный интерфейс и функционал 1.6.7. Приложение сотрудника работает на Rust + Tauri, основная серверная служба — на Rust с прежней PostgreSQL. Доставка выполняется подписанными пакетами через существующее обновление; состояние офисной установки проверяется отдельно.

В текущей локальной сборке уже открываются **Подбор клиентов** и **Настройки → Моё пространство**: рабочие профили, объяснимые рекомендации, малая модель по исходам, личные ссылки, оформление, планирование поиска по профилю и передача клиента через существующий защищённый серверный сценарий. Где находятся и какие ограничения остаются: [FEATURES-2.0.md](FEATURES-2.0.md).

## Текущая основа

Tauri показывает исходный интерфейс 1.6.7 и локальный PackOnTruck. Перенесено 69 файлов; стили и порядок исходных скриптов сохранены. В HTML добавлен загрузчик совместимого Rust-транспорта. Происхождение и SHA256 каждого файла записаны в ui-source.json. В погрузке восстановлена исходная STL-модель тягача с отдельными осями, все площадки размещены в одной сцене, добавлены перелёт камеры, общий обзор и личные именованные схемы с настройками.

Клиентский транспорт переписан на Rust: закрепление сертификата до передачи пароля, проверка host_id, UDP-обнаружение, авторизация и токен в памяти Rust, передача исходных API-ответов интерфейсу. Токен удаляется из ответа входа перед передачей в WebView. Для Excel и вложений добавлен нативный диалог с атомарной записью выбранного файла.

Приложение сотрудника запускается без Python, Electron и Node.js. HTML/CSS/JavaScript остаются представлением в системном WebView. Rust-nightly закреплён на 2026-11-10, зависимости — в Cargo.lock.

SSE использует прежний резервный опрос интерфейса. Подключены защищённое хранение и перенос сеанса, закреплённый VPS-профиль, изолированные встроенные сервисы, системные уведомления без раскрытия личного содержания и нативные подписанные обновления.

## Подготовленные библиотеки

- core: права должностей/отделов, ИНН, критерии 1–50, подтверждённый действующий статус, выручка и часовые пояса, рабочие профили, рекомендации, личные сервисы, цепочки почты и защита от запоздалых ответов.
- jobs: ограниченный параллелизм, блокировки учётных записей, сроки, отмена и освобождение ресурсов.
- compute: Rayon, выбор AVX2 / NEON / обычного пути, проверки размеров/NaN/переполнения и малая модель по явным результатам взаимодействий.
- bridge: совместимость с прежним хостом, проверяемая локальным TLS-стендом.
- host: нативный HTTPS-сервер с PostgreSQL, совместимой авторизацией, правами доступа, CRM, задачами, перевозчиками, личными схемами погрузки, поиском и почтой. На отдельной PostgreSQL и TLS проверены 16 интеграционных сценариев. Подробности перехода и границы проверок — в MIGRATION.md.

Подбор уже подключён к разрешённой сервером клиентской базе и рабочим профилям. Малая модель включается только при достаточной истории разных подтверждённых исходов; иначе используются объяснимые правила. Фоновый поиск запускается через расписание существующего хоста. Перенос остальных серверных операций продолжается. Отклонённый макет в ui/ и experiments/ основным приложением не используется.

## Проверки и запуск

```powershell
cargo run -p nexsearch-desktop --locked
node tools/verify-ui.mjs
cargo test --workspace --locked
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
```

Для осмотра без обнаружения серверов задайте NEXSEARCH_NEXT_OFFLINE=1. Проверки транспорта используют только локальный TLS-стенд; офис и VPS не опрашиваются. Windows-сборка: target/debug/nexsearch.exe.

Проверки на Ubuntu, Intel Mac, ARM Mac и процессоре без AVX2 обязательны перед выпуском. Для сборки Windows нужны MSVC и WebView2; Linux — WebKitGTK 4.1; Mac — Xcode Command Line Tools. Готовому приложению Cargo, Node.js и Python не нужны.

## Производительность и безопасность

Нет глобального target-cpu=native и обязательного AVX. ARM не компилирует x86-ядро. Rayon предназначен для крупных CPU-задач, сеть — для асинхронного выполнения. Реальное ускорение пока не доказано: первоначальный микротест не показал выигрыша AVX2 на проверенном пакете.

Деньги нельзя переводить в приблизительную SIMD-арифметику. Погрузка проверяется отдельными эталонами равновесия, моментов и нагрузок по осям. Для почты заданы предельное время операции и освобождение состояния синхронизации при отказах; длительное наблюдение за реальными провайдерами остаётся необходимым после выпуска.
