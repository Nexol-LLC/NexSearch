# NexSearch 2.0 — перенос 1.6.7 на Rust + Tauri

Сохраняем интерфейс и функционал 1.6.7. Это основа 2.0, а не новый дизайн. Статус: 2.0.0-alpha.1; перенос продолжается. Рабочий офисный сервер и пакеты сотрудников не обновлялись.

## Текущая основа

Tauri показывает исходный интерфейс 1.6.7 и локальный PackOnTruck. Перенесено 68 файлов; стили и порядок исходных скриптов сохранены. В HTML добавлен загрузчик совместимого Rust-транспорта. Происхождение и SHA256 каждого файла записаны в ui-source.json.

Клиентский транспорт переписан на Rust: закрепление сертификата до передачи пароля, проверка host_id, UDP-обнаружение, авторизация и токен в памяти Rust, передача исходных API-ответов интерфейсу. Токен удаляется из ответа входа перед передачей в WebView. Для Excel и вложений добавлен нативный диалог с атомарной записью выбранного файла.

Приложение сотрудника запускается без Python, Electron и Node.js. HTML/CSS/JavaScript остаются представлением в системном WebView. Rust-nightly закреплён на 2026-11-10, зависимости — в Cargo.lock.

Полная совместимость с рабочим хостом ещё не подтверждена. SSE пока использует прежний резервный опрос интерфейса. Защищённое постоянное хранение сеанса, VPS-профиль, встроенные сторонние сервисы, системные уведомления и автоматические обновления ещё переносятся. Это условия готовности, а не функции, которые решено удалить.

## Подготовленные библиотеки

- core: права должностей/отделов, ИНН, критерии 1–50, подтверждённый действующий статус, выручка и часовые пояса, рабочие профили, рекомендации, личные сервисы, цепочки почты и защита от запоздалых ответов.
- jobs: ограниченный параллелизм, блокировки учётных записей, сроки, отмена и освобождение ресурсов.
- compute: Rayon, выбор AVX2 / NEON / обычного пути, проверки размеров/NaN/переполнения и малая модель по явным результатам взаимодействий.
- bridge: совместимость с прежним хостом, проверяемая локальным TLS-стендом.
- host: только проверочный /health на 127.0.0.1:18743; это пока не замена Python-хоста.

Библиотеки ещё требуется подключить к реальным операциям. Обучение на истории сотрудников и автоматический подбор не включены. Отклонённый макет в ui/ и experiments/ основным приложением не используется.

## Проверки и запуск

```powershell
cargo run -p nexsearch-desktop --locked
node tools/verify-ui.mjs
cargo test --workspace --locked
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
```

Для осмотра без обнаружения серверов задайте NEXSEARCH_NEXT_OFFLINE=1. Проверки транспорта используют только локальный TLS-стенд; офис и VPS не опрашиваются. Windows-сборка: target/debug/nexsearch.exe.

Проверки на Ubuntu, Intel Mac, ARM Mac и процессоре без AVX2 обязательны перед выпуском. Для сборки Windows нужны MSVC и WebView2; Linux — WebKitGTK 4.1; Mac — Xcode Command Line Tools. Готовому приложению Cargo, Node.js и Python не нужны.

## Производительность и безопасность

Нет глобального target-cpu=native и обязательного AVX. ARM не компилирует x86-ядро. Rayon предназначен для крупных CPU-задач, сеть — для асинхронного выполнения. Реальное ускорение пока не доказано: первоначальный микротест не показал выигрыша AVX2 на проверенном пакете.

Деньги нельзя переводить в приблизительную SIMD-арифметику. Погрузка требует отдельных эталонов равновесия, моментов и нагрузок по осям. Исправление зависающей синхронизации почты проверено также в исходниках 1.x; сотрудникам оно пока не доставлялось.
