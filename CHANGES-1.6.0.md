# NexSearch 1.6.0

- Добавлен встроенный VPN для доступа к офисному хосту извне. В настройках появилась вкладка VPN; директор может подключить офисный хост из интерфейса. По умолчанию используется сеть организации Tailscale, также можно указать доступный HTTPS-сервер Headscale. Хост и каждое устройство сначала однократно авторизуются в одной сети, затем подключаются при запуске автоматически. В офисе предпочтение отдаётся локальному соединению. Проверка сертификата и обычный вход в NexSearch сохраняются.
- VPN открывает только NexSearch: он не меняет интернет-маршруты компьютера и не открывает PostgreSQL или всю офисную сеть. Настоящее подключение через интернет требует первичной авторизации владельцем сети; локальные автоматические проверки не заменяют эту проверку.

- В списке найденных компаний, клиентской таблице, канбане и карточке отображаются часовой пояс и текущее местное время по региону регистрации. Для неоднозначного региона без города пояс не подставляется наугад.
- Карточка компании разделена на сведения, работу, контакты, финансы и письма. Звонок, дополнительные контакты, история звонков и новая задача находятся сверху.
- Добавлен отдельный поиск по корректному ИНН организации из 10 цифр. Проверка выполняется через Чекко; недействующие компании не добавляются, закреплённые за другим сотрудником не дублируются. Показываются опубликованные сведения, доступные источнику и тарифу.
- Исправлено переключение канбана клиентов и общей таблицы перевозчиков. Предыдущие строки очищаются при переходе, запоздавшие ответы и старые загрузки списков не подменяют текущий раздел.
- Добавлена личная почта IMAP с папками, загрузкой писем, отметками прочтения, вложениями, ответами и отправкой через SMTP. Входящие синхронизируются на хосте примерно раз в минуту; ранние письма загружаются по кнопке. Поиск работает по уже загруженной почте.
- Каждый сотрудник подключает свои ящики самостоятельно. Для Яндекса нужны разрешённый IMAP и пароль приложения; используются TLS-подключения 993 и 465. Пароли шифруются ключом хоста и не возвращаются клиентам, а чужие ящики недоступны даже руководителям.
- В карточке компании показывается личная переписка с известными адресами. Есть поиск адреса в своей входящей почте по названию или строке поиска и сохранение найденного адреса в рабочие контакты после проверки сотрудником.
- В колокольчике сохраняются новые письма, назначенные задачи, изменения задач, напоминания о сроках и завершения поиска. Есть счётчик непрочитанного, отметка прочтения и переход к письму или задаче; повторные проверки не создают одинаковые уведомления.
- При создании задачи выбирается исполнитель. Логист может ставить задачи себе, руководитель — себе и логистам своего отдела, директор — всем действующим подтверждённым сотрудникам. Исполнитель видит назначение и может обновить результат; автор получает уведомление.
- Миграция базы 16 добавляет новые возможности без удаления существующих клиентов, перевозчиков и истории. Подготовлена совместимость миграции с уже установленным обновлятелем 1.5.1.

## Проверка перед публикацией

Автоматические проверки используют отдельный PostgreSQL и подменённые почтовые серверы. Настоящий ящик проверяется сотрудником при подключении: SMTP-отправка реальных писем и вход в личные аккаунты без участия владельца не выполняются.

Для проверки интерфейса: `python network/tests/preview16.py`, затем `node network/tests/ui/workflow16.cjs` с Playwright из среды разработки. Это отдельная учебная база на локальном компьютере; она не подключается к рабочему серверу и не использует рабочие почтовые пароли.

Настройка Яндекса: https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others
