# NexSearch 1.4.1

Сетевая CRM для логистики: общий проверенный каталог компаний, личные клиенты, канбан, звонки, задачи, заявки, общие перевозчики с автопарком, ставки с датой и PackOnTruck с нагрузкой по каждой оси.

`host` — серверная ветка. `employe` — ветка сотрудников. Полные Windows/macOS/Linux комплекты находятся в Releases. В Git отсутствуют базы, ключи Чекко, пароли, приватный TLS-ключ и ключ подписи.

Ubuntu-хост работает как системная служба без графического интерфейса. PostgreSQL доступен только локально. HTTPS использует закреплённый сертификат в приложениях; сеансы шифруются DPAPI/Keychain. При регистрации доступ подтверждает директор.

После изменения кода GitHub Actions собирает и подписывает пакет Ed25519. Сервер ежедневно в **10:00 Europe/Moscow** проверяет обе ветки. Из-за запрета deploy keys в организации учётные данные GitHub находятся только в `/etc/nexsearch/github.json` (root, 0600); рекомендуемый вариант для дальнейшего ограничения прав — GitHub App или отдельный токен только на чтение этого репозитория. Обновление хоста проходит после резервного копирования с проверкой восстановления; при ошибке возвращается прежняя программа. Клиенты получают подписанные пакеты своей ветки через защищённое соединение с хостом и устанавливают при закрытии программы. Секретный GitHub-токен сотрудникам не передаётся.

Настройки → Хост: IP, доступность, CPU, RAM, свободный диск, очередь поисков. Настройки → Обновления: состояние проверки и подготовленного пакета.

Настройка сервера: `ubuntu/install.sh`. Службы: `nexsearch`, `nexsearch-update.timer`, `nexsearch-backup.timer`. Поиск в LAN: mDNS UDP 5353 и резервный broadcast UDP 8742; приложение TCP 8743. Эти порты должны быть разрешены между сотрудниками и сервером.

Сборка Windows: `python build_windows.py all`. Mac комплект использует собственные нативные Python/Electron и офлайн-зависимости. Код поиска и CRM не использует ИИ.
